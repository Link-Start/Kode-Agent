## 1. 问题描述

### 1.1 问题场景

为提高终端透明背景下的可读性，将辅助文字和强调文字的最小对比度提升到 4.5:1，并让 `/config` 默认显示“快速开始”、通过 Tab/a 进入高级设置。

### 1.2 具体表现

首次运行聚焦测试时，3 个旧主题断言仍按 3:1/3.6:1 与旧最大比值校验；另一个 Ink 鼠标测试直接在 `/config` 初始画面查找“Stream responses”，因该行已移至高级页面而失败。

### 1.3 错误信息

```text
Expected: <= 6.4; Received: 6.547107066694314
Expected: >= 0; Received: -1 (ConfigScreen: Stream responses)
```

## 2. 根本原因分析

### 2.1 问题分析过程

1. 聚焦测试先报告主题对比度上限与最小值不一致，说明运行时主题算法已变更但专门断言未同步。
2. 随后 Ink 测试找不到设置行；输出显示“Quick start”，确认不是鼠标解析问题。
3. 定位为同一功能改动中遗漏了测试的可见页面状态与旧的数值边界，而非配置写入或鼠标事件回归。

### 2.2 直接原因

- `packages/core/src/test/unit/theme-contrast.test.ts:101-126` 保留旧的强调/辅助色阈值。
- `packages/core/src/test/e2e/tui-interactions.overlays.test.tsx:438-443` 假定设置列表在初始视图可见。

### 2.3 根本原因

实现前只检查了主题角色和配置页面本身，未将“默认页面状态”与“新的无障碍验收阈值”作为同一次变更的测试契约同步更新。

### 2.4 为什么没有提前发现

本次变更没有先运行覆盖主题与 `/config` 鼠标交互的聚焦测试；静态检查无法发现这些运行时假设。

## 3. 解决方案

### 3.1 根本解决方案

- 将主题测试中的强调与辅助文字断言更新为 4.5:1，并验证新增高对比主题。
- 在鼠标回归测试中先发送 Tab、确认“Advanced preferences”出现，再定位并点击“Stream responses”。
- 为高对比主题的筛选测试使用不会在终端输出中丢失尾随空格的连字符查询。

### 3.2 影响范围评估

仅修改测试前置状态及可访问性阈值；不改变模型、密钥或权限数据，也不改变鼠标事件协议。

## 4. 预防措施

### 4.1 代码层面

- [x] 将正常尺寸的辅助/强调文字对比度阈值集中在主题模块中。
- [ ] 后续增加共享的“配置页导航到高级设置”测试帮助函数，避免各测试重复假定初始页。

### 4.2 测试层面

- [x] 在修改主题阈值与默认视图后运行 `theme-contrast` 和 `tui-interactions.overlays`。
- [ ] 为透明背景下不发出 ANSI faint 的关键页面增加 ANSI 快照断言。

## 5. 经验总结（一句话）

改变可访问性阈值或默认视图时，必须将运行时行为、数值断言和交互测试的初始状态视为同一份契约同步更新。
