## 1. 问题描述

### 1.1 问题场景

用户在没有 Bun 或本地依赖的已安装包中执行 `kode --help-lite`，用该输出确认可用参数。

### 1.2 具体表现

输出将 `-c` 标成 `--cwd <cwd>`；但实际 CLI 中 `-c` 是 `--continue`，工作目录仅支持 `--cwd`。轻量帮助还遗漏了 `--headless` 和恢复会话选项。

### 1.3 错误信息

```text
  -c, --cwd <cwd>      Set working directory
```

## 2. 根本原因分析

### 2.1 问题分析过程

1. 对源码入口和已发布包装器分别运行 `--help-lite`。
2. 源码入口正确显示 `--cwd`、`-r/--resume` 和 `-c/--continue`。
3. 已发布包装器的输出将 `-c` 复用了过时的工作目录说明。
4. 构建脚本会把 `scripts/cli-wrapper.cjs` 复制为根目录 `cli.js`，因此源包装器与已生成入口必须同步修复。

### 2.2 直接原因

`scripts/cli-wrapper.cjs` 的静态帮助字符串没有随 Commander 参数变更更新；根目录 `cli.js` 是它的受版本控制构建产物。

**相关代码位置**：`scripts/cli-wrapper.cjs`、`cli.js`

### 2.3 根本原因

- **设计层面**：轻量帮助为避免加载完整运行时而维护了一份手写参数清单。
- **测试层面**：既有 wrapper 测试只断言包含基础 usage/help，未验证易冲突的短参数映射。

## 3. 解决方案

### 3.1 根本解决方案

- 将轻量帮助与实际入口对齐：`--headless`、`--cwd`、`-r/--resume`、`-c/--continue`。
- 同步更新受版本控制的 `cli.js` 构建产物。
- 扩展 `cli-wrapper.test.ts`，断言 `-c` 映射为 `--continue`，且绝不再映射为 `--cwd`。

### 3.2 影响范围评估

仅改变无副作用的帮助文本与回归测试；不改变命令解析、认证、会话或权限行为。

## 4. 预防措施

### 4.1 代码层面

- [x] 将包装器帮助中的高频参数与实际 CLI 同步。
- [ ] 后续新增或修改短参数时，同时更新轻量帮助。

### 4.2 测试层面

- [x] 为 `-c/--continue`、`--cwd`、`--resume` 和 `--headless` 添加 wrapper 回归断言。
- [ ] 在发布前增加轻量帮助与 Commander 注册参数的自动对照。

## 5. 经验总结（一句话）

当发布包装器维护独立的静态帮助时，短参数映射必须有行为级回归测试，否则正确的解析器也无法弥补错误的用户指引。
