## 1. 问题描述

### 1.1 问题场景

用户通过交互式模型配置、YAML 导入或旧版配置建立模型 profile，然后运行模型请求、查看模型列表或启用 API 调试日志。

### 1.2 具体表现

新建和更新 profile 可以写入 `apiKey` 明文字段；YAML 导入会读取环境变量并把解析出的值写回配置。旧 profile 也能直接作为请求凭据。部分 API 调试事件还会记录凭据前缀。

### 1.3 错误信息

没有单一运行时报错；风险表现为持久化配置或调试日志中可能包含可用凭据。为避免二次泄露，本复盘不记录任何实际值或前缀。

## 2. 临时解决方案

### 2.1 方案描述

无人工迁移、删除或重写用户既有配置。旧 profile 在没有 `apiKeyEnv` 时被阻断，并给出仅含环境变量名称的配置与轮换提示。

### 2.2 止血效果

新建/更新 profile 和 YAML 导入不再写入明文；运行时只从命名的环境变量读取；模型列表与模型管理器输出会脱敏；API 调试事件不再记录 key 前缀。

### 2.3 临时方案的局限

旧文件中的历史字段按用户要求保留，不会被自动删除；用户仍需在确认后自行轮换旧凭据并清理历史配置。

## 3. 根本原因分析

### 3.1 问题分析过程

1. 审计 `ModelProfile`、模型保存和运行时解析，确认 `apiKey` 同时被存储和用于请求。
2. 对照 YAML 导入逻辑，确认 `fromEnv` 会被立即解析并持久化到 `apiKey`。
3. 检查模型选择器、确认页和 `models list`，定位到旧字段可以进入 UI 状态或被转换为“已配置”状态。
4. 对运行时源代码做敏感字段扫描，定位到 OpenAI 与 Anthropic 调试事件中的 `apiKeyPrefix`。
5. 将凭据引用集中为 `apiKeyEnv`，并在模型解析、保存、导入和展示边界逐一改为失效关闭。

### 3.2 直接原因

配置模型把“凭据内容”与“凭据引用”混为同一字段；运行时没有强制环境变量引用，调试结构化数据也没有遵循不可逆脱敏原则。

**相关代码位置**：`packages/config/src/models/credentials.ts`、`packages/core/src/model/resolution.ts`、`packages/config/src/modelYaml.ts`

### 3.3 根本原因

- **设计层面**：缺少凭据只在运行时解析、配置只存引用的明确边界。
- **开发层面**：交互式表单把一次性校验输入直接传给持久化层。
- **流程层面**：此前的 YAML 与调试日志回归测试只验证功能，未覆盖“不得持久化或输出秘密”的负向场景。

### 3.4 为什么没有提前发现

- 代码审查阶段：未将模型 profile 当作凭据边界审查。
- 测试阶段：缺少“旧明文 profile 必须拒绝运行”和“YAML `apiKey.value` 必须拒绝”的回归用例。
- 监控告警：调试日志字段没有敏感字段白名单或拒绝清单。

## 4. 解决方案

### 4.1 根本解决方案

- 新 profile 只持久化 `apiKeyEnv`，且 `apiKey` 固定为空。
- 模型运行时解析仅接受当前进程中 `apiKeyEnv` 指向的环境变量；缺失引用或缺失变量均失败关闭并提示轮换历史密钥。
- YAML 只接受 `apiKey.fromEnv`/`apiKeyEnv`，拒绝 `apiKey.value`，且导入不会解析环境变量后写回配置。
- 对外模型列表和模型管理器结果统一脱敏；确认页不再显示密钥或其长度。
- 删除 OpenAI/Anthropic 调试事件中的 `apiKeyPrefix`。

### 4.2 影响范围评估

历史明文 profile 会停止用于请求，直到用户显式配置环境变量引用；这是有意的安全兼容性变化。不会自动读取、迁移、打印或删除历史密钥，也不会改变 SDK 上游目录。

## 6. 经验总结（一句话）

配置文件只能保存凭据引用，任何实际密钥只能在受控运行时读取，并且日志不得保留可逆片段。
